# 安装与旧名称迁移

## 更新范围

更新器只从固定的 Gitee 官方仓库读取完整集合。它不接受任意下载地址，不执行下载包内的安装脚本，不更新其他来源的 Skill。GitHub 历史安装渠道的已知副本按文件内容识别；本更新入口统一使用 Gitee，避免不同渠道内容不一致。

`--check` 下载并核验到临时目录，仅报告差异；`--apply` 才替换已安装文件。两个模式都需要网络与仓库读取权限。发布前的本地开发分支尚未进入远端时，正式更新命令仍读远端，不能用来安装未发布改动。

## 可以自动迁移的安装

- 与 c3c8387 版本记录完全一致的旧目录，包含 skills CLI 已转成小写的目录及手动复制的原英文名称。
- 与本次官方包完全一致的目录。
- 与本更新器此前记录完全一致的目录。

来源检查比较完整文件集合和 SHA-256，不能仅凭名称或 `collection` 字段认定来源。旧版本文件签名保存在更新 Skill 内的 `references/legacy-installations.json`。

其他更早或自行修改的副本会报告冲突。先将自己的改动另存到用户选择的位置，再根据需要移开冲突目录并重试；更新器不会自动删除或覆盖这些文件，也不会要求用户丢弃修改。

## 文件替换与失败处理

所有目标都通过检查后，先暂存全部新技能、备份旧内容，再迁移旧目录和写入规范名称。中途失败恢复原安装。备份位于 `~/.liskill/backups/<本次标识>/`，其中 `locations.json` 记录原位置；它们不在技能扫描目录中。`~/.liskill/install-state.json` 只记录已安装文件的校验值，用于下一次识别修改。

备份是完整旧文件，不是用户素材存档功能。用户作品、其他技能和原始软链接指向的源码目录不在更新范围内。软链接被迁移时，只替换安装入口，保留其指向的源码。

更新进程被强行结束、断电等进程外中断时，不能保证自动回滚；可根据备份和原位置记录恢复。正常异常路径由更新器回滚，不应把失败当成成功。

## 客户端

默认使用通用 Agents 目录；仅当 Claude Code 用户目录存在时增加它的专属目录。Codex 的已识别旧专属入口迁移到通用目录，避免重复发现。其他客户端通过 `--skills-dir` 指定实际目录，或自行导入完整 Skill 文件夹。

如果多个客户端共享同一个实际目录，更新器按解析后的路径去重。对嵌套目录和误指用户家目录、根目录的参数直接报错。
