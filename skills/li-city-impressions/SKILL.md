# 城市印象反转

## 使用前说明

开始使用时主动告知：「这个 skill 目前是结构型，填充物需要我们一起补充，不会自动产出完整文稿」。城市数据仅有未核验示例；需要与用户补齐并确认真实经历和城市细节。 不把待补结果当成已核验成稿。

把用户对一个城市的真实观察整理成先制造误解、再用事实完成反转的短视频脚本。

## 核心结构

按以下顺序组织内容：

1. 负面强观点开头
2. 4—6 个负面印象或常见误解
3. 1—2 件真实反转小事
4. 4—6 个正面细节
5. 一句呼应开头的情绪金句

目标长度为 500—600 字，适合约 2 分钟口播。

## 参考材料

- 第一次使用该结构、需要理解完整重庆案例或仿写槽位时，读取 `references/case-study.md`。
- 需要检查目标城市是否已有参考数据时，读取 `references/city-data.csv`。
- 用户已经提供完整素材时，直接按本文件执行，不必重复加载完整案例。

参考材料只用于启发，不得直接当作城市事实。涉及景点、工资、物价、房价、消费和群体印象的内容，必须让用户确认。

## 执行流程

### 1. 确认目标城市和真实关系

询问：

> 你想写哪个城市？你是本地人、游客，还是曾经在那里生活过？

记录用户与城市的关系。优先使用亲历素材。

### 2. 检查城市参考数据

读取 `references/city-data.csv`，按城市字段匹配。

如果存在：

- 提取开头模板、负面印象、反差比喻和热度信号作为参考。
- 明确告诉用户这些内容需要逐条确认。
- 用户提供的信息与数据冲突时，优先采用用户确认的真实信息。

如果不存在：

- 不报错。
- 告知用户数据库暂时没有该城市。
- 进入素材挖掘流程，不得补写未经确认的城市细节。

### 3. 确认负面强观点

先让用户说出最想反转的一种城市误解。必要时提供句式方向：

- “这个城市是我去过最骗人的城市。”
- “这个城市应该对全国人民道歉。”
- “没去这个城市之前，我以为……”

开头可以尖锐，但后文必须用真实内容回应，不能只为攻击制造情绪。

### 4. 挖掘负面印象

每次只问一个方向，收集 4—6 个具体信息点：

- 景点与实际体验
- 饮食与刻板印象
- 工资、物价和消费
- 地形与交通
- 外地人对当地人的第一印象

把抽象评价追问成具体场景、数字或行为。无法核实的内容标记为待确认。

### 5. 挖掘真实反转小事

询问：

> 有没有一件真实发生的小事，让你改变了对这个城市的看法？

故事尽量包含：

- 发生地点
- 具体人物
- 对方做了什么
- 用户原本的预期
- 最终为什么改变判断

没有真实反转故事时停止生成完整脚本，继续帮助用户寻找素材，不得虚构。

### 6. 挖掘正面细节

收集 4—6 个正面信息点，优先回应前文的负面印象。例如：

- 景点拥挤 → 换时间或角度后的独特景色
- 说话声音大 → 直接、热情的性格体验
- 工资不高 → 经用户确认的生活成本反差

也可从服务态度、夜生活、生活方式和当地人的松弛感继续追问。

### 7. 设计结尾金句

复用开头的关键词，但改变它的含义。结尾必须来自用户的真实感受，避免空泛的城市宣传口号。

### 8. 生成脚本

按以下格式输出：

```text
【开头强观点】

【负面印象堆叠】

【真实小事反转】

【正面翻盘】

【结尾金句】
```

随后补充：

- 脚本字数和预计时长
- 建议搭配的拍摄画面
- 来自用户亲历的内容
- 来自参考数据、仍需核实的内容

### 9. 执行八步自检

检查：

1. 选题是否能用一句话说明。
2. 是否属于城市印象反转型内容。
3. 用户真正想表达的核心判断是否明确。
4. 开头是否能吸引目标用户，又不会构成无依据攻击。
5. 呈现形式是否适合口播、边走边说或 B-roll。
6. 字数与时长是否匹配。
7. 信息密度是否接近平均 5 秒一个信息点。
8. 目标用户是本地人、游客还是两者兼有，内容解决什么认知或情绪问题。

## 内联案例库

### 典型案例：重庆印象反转

> 开头先说重庆“骗人”，接着列举景点、饮食、工资和地形带来的负面预期；中间通过当地人主动带路等真实小事改变情绪；后半段逐项回应前面的误解；结尾重新解释“骗人”这个词。

- 结构要点：负面内容必须在后文得到回应，反转小事承担情绪转折。
- 使用要点：城市细节和反转故事必须由用户确认，不能把参考案例换个城市名直接套用。

### 反面案例：只有攻击，没有反转

> 开头连续批评一个城市，后面只堆旅游宣传词，没有真实人物、事件或前后对应关系。

- 问题：负面情绪没有被事实反转，内容容易变成地域攻击。
- 处理：缺少真实反转故事时停止生成，继续挖掘素材。

## 边界

- 不编造城市事实、人物故事或热度数据。
- 不把数据库中的单条案例概括成整个城市或群体的固定特征。
- 数据生命周期为“衰退”时，提醒用户更换角度或重新验证热度。
- 每次只追问一个素材缺口，等待用户回答后继续。

## 流水线衔接：内容卡与下一步

本技能是李同学「一步一技能」12 步中的第 6–8 步「脚本形式 / 开头 / 完整脚本」（城市印象反转形式）。单独使用时照常执行上文流程；从 `li` 主入口或上一步「继续」进来时，按下面衔接。

**内容卡**：用户当前工作目录里的 `内容卡_<主题>.md`，一条作品一张，栏目固定为：素材 / 选题与角度 / 受众 / 值不值得拍 / 转发判断 / 形式 / 开头 / 脚本 / 审核记录 / 发布，卡头有「当前进度」和「账号定位」两行。

- 开始前查找 `内容卡_*.md`：有一张就读取，沿用已确认的内容，不让用户重复提交；有多张先问是哪一条；用户粘贴了「交接卡」就以它为准。没有卡时，在用户做出第一个确认后新建，空栏目写「（待填）」。
- 读卡时：「素材」「选题与角度」里已确认的城市、经历和反转故事直接沿用，只追问缺口。
- 本技能只更新「形式」（写「城市印象反转」）、「开头」（写开头几句）和「脚本」（写用户确认的脚本），以及卡头「当前进度」；其他栏目只读。发现与其他栏目矛盾时告诉用户，由用户决定。只写用户确认过的短结论，不贴完整分析。
- 不能写文件的客户端（如豆包、网页对话）：在回复末尾输出一个代码块，第一行写「【交接卡】复制整段，下一步发给我」，下面是整张卡的最新内容。

**带练模式（默认）**：负面强观点、真实反转小事、脚本成稿都由用户确认——到这些判断点必须停下，给出选项和推荐，等用户选。用户选完才更新内容卡并输出下面的结尾。用户回复「继续」时，定位并读取下一步技能的 SKILL.md（宿主已发现的技能路径，或同级目录按机器名称查找），带着内容卡进入；不越过用户的选择自动连跑。下一步还在建设中时如实说明，并给出替代做法。

缺少真实反转故事、停止生成时，不输出结尾，继续帮用户挖素材。

**结尾格式**：

```
✅ 第 8 步完成：城市印象脚本已确认（<城市>，反转点「<一句话>」）
👉 下一步是第 9 步：八步审核（li-eight-audits 八大审核法），回复「继续」开始
也可以：回到第 3 步换角度 ／ 补素材后重写这一版
```
