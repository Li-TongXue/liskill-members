# 脚本形式（第 6 步）

一条选题能拍成很多样子。本技能只做一件事：帮用户在李同学的结构库里选一个合适的结构，并说清楚用这个结构还缺哪些素材。不写开头，不写全稿。

## 随包材料

- `references/structure-index.md`：结构索引，按类型分组，每个结构一行。每次都先读它。
- references/structures 目录：每个结构一个文件，文件名就是结构名。用户选定结构后，读取对应文件的「需要的素材」一节。

只从结构库里推荐。库里没有合适的结构时如实说明，不自己编一个结构。

## 对话原则

1. 每次只问一个问题；内容卡和对话里已有的信息不再问。
2. 推荐最多 3 个结构，每个都要说清为什么适合这条选题，不只报名字。
3. 选哪个结构由用户决定。给出推荐顺序，但不替用户定。
4. 用户亲身经历的事，不能由 AI 代编。

## 固定流程

### 第一步：确认选题和素材

从内容卡（见文末「流水线衔接」）或对话中取得：

- 选题：一句话，这条视频要讲什么；
- 素材：已经有的事件、经历、案例、数字、画面；
- 受众：拍给谁看（没有就先不问）。

没有选题时，说明这一步需要先有选题，并建议回到第 3 步；用户坚持直接选形式时，请他用一句话说出想讲的事。

### 第二步：判断内容类型

按顺序做四个测试，第一个成立的就是主类型：

| 测试 | 成立就是 |
|---|---|
| 把讲的人换掉，内容还有价值吗？ | 知识型：价值来自客观信息 |
| 换一个没有这段经历的人来讲，内容还成立吗？不成立 | 经历型：价值来自亲身事件 |
| 核心是「我认为 X」，别人可以合理反驳吗？ | 判断型：价值来自主观立场 |
| 把声音关掉，画面或行动本身还有价值吗？ | 展示型：价值来自可观看的行动 |

三个常见误判：

- 「3 个方法」听起来像知识型，但这 3 个是用户的个人立场、同行会主张相反做法 → 判断型；同行普遍认可、照着做就能用的方法仍是知识型；
- 开头情绪化（「假如我是……」「你一定……」）不决定类型，看内容本身；
- 引用多年经验只是背书；价值来自信息本身时仍是知识型。

门店、工地、工厂这类有可拍现场动作的内容，先做展示型测试，再做经历型测试。主类型只用来缩小范围；最终以选定结构在索引里所属的类型为准。

同时判断这条选题还能支持哪些类型。例如：没有可拍的现场就做不了展示型；用户没有亲身经历就做不了经历型。

用一两句话告诉用户主类型和判断依据。

### 第三步：推荐 2–3 个结构

读取 `references/structure-index.md`，优先从主类型里挑，素材支持时可以跨类型。每个候选写：

```markdown
**结构名**（类型｜难度）
为什么适合这条选题：
需要的素材：
你已经有的：
还缺的：
```

推荐前可以问 1–2 个可行性问题（例如能不能去现场拍、有没有员工配合），不计入第四步的追问次数。

排序时先看素材缺口小不小，再看难度。选题明显是城市印象或故事 Vlog 时，按索引最后一节转到对应技能，并说明原因。

然后问：

> 你想用哪一个？也可以说说哪个最不像你会拍的。

### 第四步：列出素材缺口

用户选定后，读取该结构文件的「需要的素材」表，逐项对照：

| 素材 | 状态 | 处理 |
|---|---|---|
| …… | 已有／缺 | 已有：写出用哪条素材；缺：按表里「缺了怎么办」处理 |

缺口的处理：

- **追问**：一次只问一个，最多问 3 个最关键的；先问用户一句话就能答的（账号名、原话、具体数字），再问需要回忆的；
- **占位**：第 8 步写稿时写成【待补：……】，现在只记下来；
- **可起草**：只限常识类素材，第 8 步写成【示例，请改成你的】。

用户说「先写吧」时停止逐个追问：把剩下的缺口一次列出来，告诉用户能顺手答的现在就答，答不上的全部转成占位。不让追问卡住流程。

### 第五步：交付

素材缺口按素材表里状态为「缺」的行数计算。

```markdown
## 脚本形式

内容类型：主类型（辅类型，如有）
选定结构：结构名（难度）
为什么用它：一句话
素材对照：
- 已有：……
- 待补：……（第 8 步会写成占位）
- 可起草：……
```

## 质量检查

- 是否先确认了选题，而不是直接推荐结构？
- 类型判断是否按四个测试，并说明了依据？
- 推荐是否都来自结构库，最多 3 个，并写清为什么适合？
- 是否由用户选定结构？
- 素材缺口是否逐项对照了结构文件，而不是凭印象？
- 是否没有替用户编造亲身经历？
- 追问是否一次一个、最多 3 个，用户要先写时是否立即停止？

## 流水线衔接：内容卡与下一步

本技能是李同学「一步一技能」12 步中的第 6 步「脚本形式」。单独使用时照常执行上文流程；从 `li` 主入口或上一步「继续」进来时，按下面衔接。

**内容卡**：用户当前工作目录里的 `内容卡_<主题>.md`，一条作品一张，栏目固定为：素材 / 选题与角度 / 受众 / 值不值得拍 / 转发判断 / 形式 / 开头 / 脚本 / 审核记录 / 发布，卡头有「当前进度」和「账号定位」两行。

- 开始前查找 `内容卡_*.md`：有一张就读取，沿用已确认的内容，不让用户重复提交；有多张先问是哪一条；用户粘贴了「交接卡」就以它为准。没有卡时，在用户做出第一个确认后新建，空栏目写「（待填）」。
- 读卡时：「选题与角度」「素材」「受众」里已确认的内容直接用于第一步和第四步，缺什么再问。
- 本技能只更新「形式」（写第五步的交付内容）和卡头「当前进度」；本步用户新补充的素材写进「形式」的素材对照，第 7、8 步以它为素材来源；其他栏目只读。发现与其他栏目矛盾时告诉用户，由用户决定。只写用户确认过的短结论，不贴完整分析。
- 不能写文件的客户端（如豆包、网页对话）：在回复末尾输出一个代码块，第一行写「【交接卡】复制整段，下一步发给我」，下面是整张卡的最新内容。

**带练模式（默认）**：选哪个结构由用户决定——到这个判断点必须停下，给出候选和推荐顺序，等用户选。用户选完、素材对照完成后，才更新内容卡并输出下面的结尾。用户回复「继续」时，定位并读取下一步技能的 SKILL.md（宿主已发现的技能路径，或同级目录按机器名称查找），带着内容卡进入；不越过用户的选择自动连跑。

**结尾格式**：

```
✅ 第 6 步完成：选定「<结构名>」（<结构所属类型>），素材缺口 <N> 项
👉 下一步是第 7 步：开头（li-script-opening 开头），回复「继续」开始
也可以：回到第 3 步换选题角度 ／ 先补齐待补素材再继续
```

选中城市印象或故事 Vlog 时，👉 一行改为转到 `li-city-impressions` 或 `li-story-vlog`，它们自带第 6–8 步。
