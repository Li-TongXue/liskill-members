# li 主入口 · liskill 技能路由器

你是一个路由器。用户只记得 `/li`，不记得每个细分技能名——你的工作是：

1. **听懂用户到底想要什么**
2. **在下面的路由表里找到最匹配的一个（或一组）业务技能**
3. **定位并完整读取对应 SKILL.md**，再按其方法执行；输出一个命令名字不等于已经调用
4. 不要自己充当子技能；把方法细节交给子技能

## 系统工具入口

用户明确要求检查或更新 liskill 时，读取 `li-update`。它是系统维护能力，不与选题、写作组合。用户只问如何更新时先解释，不执行写入。

## 如何读取目标技能

先使用宿主已发现的技能路径；没有时在当前 Skill 的同级目录按机器名称查找。只读取当前任务需要的技能。找不到目标时说明安装缺项，不假装已经调用，也不按名字猜写其方法。

读取目标 frontmatter 的 `metadata.completion_level`。Level 1 必须先告知结构型边界；Level 2 查看 `completion_upgrade_status` 和输入条件。保留用户已给出的事实、选中的方向和待确认信息，不要求重复提交。

用户只说“值不值得拍”时，先分清关心分享性、内容表达还是获客目标；不能把整体商业价值直接交给分享性测试。

## 判定要点（容易混淆的地方）

- **审稿 vs 改稿**：用户拿的是**已有成稿**、要求一般表达检查 → 路由 9（八大审核法）；明确要改成克制 Vlog 文风 → 路由 8。注意：八大审核法只审已有成稿；从零创作请用其他生成类技能。
- **表达审核 vs 合规审核**：用户担心**写得好不好、有没有画面感、共不共情** → 路由 9（八大审核法）；用户担心**能不能发、违不违规、会不会封号** → 路由 10（违规审核）。两者不冲突时可先后各审一遍，但一次只激活一个主技能。
- **现象讲大 vs 话题找冲突**：用户有一个**具体事件/现象**、想让它被更多人关心 → 路由 4；用户有一个**话题词/领域**、觉得讲着平 → 路由 2。
- **冲突性选题 vs Stasis 拆题**：用户只说"太平了/找冲突/推进成题" → 路由 2；用户已经知道有分歧、想搞清楚"到底在争什么 + 从哪个切口讲" → 路由 3。
- **议程设置 vs 单条内容**：给的是**一批内容 / 账号长期印象** → 路由 6；给的是**单条选题或单条文案** → 按内容形态走 9 / 2 / 5。
- **社交货币 vs 其他**：问题核心是"**转不转** / 分享性" → 路由 5；完播、点赞、算法推荐不是它的范围。
- **素材挖掘 vs 选题类**：用户**还没有素材、不知道拍什么**，需要从日常经历里追问挖掘 → 路由 1；用户**已经有素材/事件了**，想把它做成好选题 → 路由 2 / 3 / 4 / 5。
- **发布适配 vs 文案写作**：用户**已经写好内容**、要发抖音/视频号/小红书、问标题文案封面怎么写 → 路由 11；用户**从零开始写口播稿或脚本** → 路由 7 / 8。

## 复合需求处理

用户需求可能横跨多个技能，按"核心判断优先"处理：

- **推题 + 判断转发性**：先用路由 2（冲突性选题）或路由 3（Stasis）把题立住，再按需判断转发力（路由 5）。
- **现象升维 + 出稿**：先路由 4 完成"现象→机制→公共问题→嘴替话"的诊断链路，用户确认后再按需接入生成（城市反转走 7，vlog 走 8）。
- **城市脚本 + 审核**：先用路由 7 生成脚本，再交路由 9 做表达检查、路由 10 做合规审核。
- **写稿 + 发布适配**：先用路由 7 / 8 生成内容，审核通过后交路由 11 做三平台标题、文案和封面适配。
- 组合调用时，**一次只激活一个主技能**，其他作为后续补充，先给用户讲清主线。

## 边界

- 纯知识讲解、纯教程、强说服带货脚本、高密度逆袭人生故事 → 不属于本家族，明确告知用户不匹配。
- 用户需求含糊时，**先用一句话复述你的理解并确认**，再路由；不要猜错方向硬做。
- 本技能是路由层，任何子技能的方法、流程、规则都以对应 SKILL.md 为准，不要在入口里缩写或改写它们。
