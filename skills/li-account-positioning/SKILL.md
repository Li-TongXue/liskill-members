# 账号定位（第 1 步）

李同学讲定位，第一句话是：「我是火锅店老板」不是定位，那只是职业。定位是**从竞争对手出发，在用户眼中找一个优势位置**；最好的办法是**找空位**。

本技能带一个实体老板（餐饮、美业、装修、门店服务等）从零走完这件事，交付一个**可以马上开拍的暂定定位**。李同学同样强调：定位不是一次定死的，是「在走的路上不断发现」。所以交付物里一定带验证信号和复盘节点。

## 随包材料

- `references/positioning-method.md`：李同学定位方法的原话依据、六类空位的实体店例子、三条件的判断细则和理论边界。第四步找空位之前读一次；用户问「为什么这么定」时据此解释。

## 对话原则

1. **每次只问一个问题**；用户一次说了很多，就直接用，不再重复问。
2. **到判断点必须停下**，给选项和推荐顺序，由用户选：用户画像、主空位、人设立场、最终一句话。
3. **不编对手情况**。「同城没人做」只能来自用户查过或亲口说的事实；没查过时写【待查】，并告诉他怎么查。
4. **不劝人离开本行业**。李同学原话：「不要抛弃你本行业，在你本行业去找到更好的你。」空位从他真实的经历、手艺、资源里找。
5. **不追求九格填满**。变现、价值、用户、人设、形式、风格、区域、细分、跨界九个小定位分三层用：先定底座，再找一个主空位，最后定表达。
6. **不承诺播放量和获客数**。
7. **用户说「先给我结果」「别问了」时**：立即停止追问，用已有信息补齐，所有推测的部分标【待确认】，直接进入第六步交付。交付即视为用户接受这份暂定定位：照常更新内容卡、输出结尾，一句话定位后加「（暂定）」。流程必须能走完。

## 固定流程

### 第一步：了解这家店

开场只问一句：

> 先介绍一下你的生意：做什么的、店在哪个区或商圈、做了几年、现在主要靠什么赚钱、有没有已经在发的抖音号？想到哪说到哪。

从回答里提取：行业与品类、位置、从业年限、现有变现方式、老板本人的经历和特长、现有账号情况。缺的关键项最多追问 2 个，一次一个。

**近邻转出**：用户已经发了 20 条以上、想知道账号为什么不涨或印象散不散——这是检查已有内容，告诉他用 `li-agenda-setting`（议程设置内容定位）更合适；他坚持要重新定位时，再继续本流程。

### 第二步：要不要细定位

李同学：定位的目的是**对抗内卷**——做的人多了才需要细定位；当地正经做短视频的门店不多时，「做短视频这件事本身就是差异化」。

让用户自己查一次（一次一个问题）：

> 打开抖音，搜「<区域>+<品类>」（例如「沙坪坝 火锅」），再点进「创作灵感」看看这个品类的热门话题。同城有几个**真人老板出镜、一周至少更新 2 条**的同行号？

| 用户回答 | 判断 | 后面怎么走 |
|---|---|---|
| 0～2 个 | 竞争少，**粗定位**即可开拍 | 第四步只找 1 个最顺手的空位，不深挖 |
| 3 个以上，或用户说「很卷」 | 需要**细定位** | 第四步完整找空位 |
| 没查、不想查 | 按「需要细定位」处理，对手情况标【待查】 | 交付时把「查同城对手」写进验证清单 |

注意：竞争少也要定底座。没人卷可以不找差异，但「靠什么赚钱、要谁来」任何时候都要有。

### 第三步：底座三问——变现、用户、价值

按顺序，每项先由你根据已知信息给推荐，再让用户确认或改：

1. **变现定位：最终靠什么赚钱？** 到店消费／团购核销／预约咨询到店／加盟招商／线上卖货／教同行（知识付费）。只选一个主变现，其他写成「以后可能」。李同学提醒：产品最好由真实流量和需求反推，不必一开始就设计新产品；但现在主要靠什么赚钱必须说清。
2. **用户定位：要获得谁？** 李同学认为这是最重要的一项，「千万不要陷入自嗨」。按他的问法，列 5 个**不同领域、不同收入水平、不同场景**的候选人群，每个写成具体的一个人：

   ```markdown
   1. <谁>（<哪里/多大/收入或身份>）——在<什么场景>会想到你——他现在去找谁
   ```

   推荐 1～2 个最接近主变现的，问用户：**「你最想让哪一个人刷到你？」**——这是判断点，停下等他选。
3. **价值定位：你能给他什么？** 一句话，写成用户得到的东西（省钱、放心、面子、解压、少踩坑），不写「我们很专业」。

### 第四步：找空位（核心）

先读 `references/positioning-method.md`。从下面六个方向各想 1 个候选（粗定位时只想 2～3 个最顺手的）。每个候选必须用到第一步里用户的真实信息：

| 方向 | 问自己 |
|---|---|
| 区域空位 | 在他能服务的范围里，这个品类有没有还没人认真做的区域？ |
| 行业细分空位 | 能不能从大类里切一个更窄的品类、场景或问题，让他成为第一个？ |
| 人群空位 | 能不能只服务第三步选中的那一类人，把话说到他心里？ |
| 形式空位 | 同行都在拍什么？同样的东西换一种更像用户世界的拍法（过程、现场、对比、情景）？ |
| 身份空位 | 同样的内容，换一个用户更愿意亲近的身份讲（「张总」变「隔壁阿姨的儿子」）？身份必须是他本来就是的人。 |
| 跨界融合 | 他过去的行业、经历、特长，和现在的生意能不能叠出别人没有的东西？ |

用**三个条件**筛每个候选，三个都过才算空位：

| 条件 | 检查 | 不过的常见情况 |
|---|---|---|
| 有人要 | 第三步选中的那个人，会因为这个差异来找他吗？ | 「重庆唯一的分子料理火锅」——没人做，因为没人要 |
| 没人占 | 同城/同类里，用户脑子里是不是还没有一个现成的第一名？ | 已经有头部号在做同一件事 |
| 我占得住 | 他有真实的经历、手艺、资源或时间撑得住 30 条以上吗？ | 身份是编的，或需要他天天做他做不到的事 |

输出 2～3 个过关候选，每个一行写清三条件依据，标出推荐顺序，然后问：

> 你选哪一个做主空位？也可以说哪个最不像你。

这是判断点，停下等他选。只留 **1 个主空位**；其他写进「备选」。

### 第五步：定表达——人设、形式、风格、账号议程

围绕选中的主空位，一次确认一项：

1. **人设**：李同学说人设是「你是谁、代表什么价值观」，靠事件打出来，不靠自己说。给 2 个候选，每个写清：**帮谁说话**、**反对什么**（反对什么更容易立住）、**一件能体现它的真实小事**。问用户选哪个。
2. **形式**：口播／过程实拍／探店或上门现场／情景剧／对比测评，选 1 个主形式，说明为什么适合他（出镜意愿、时间、店里有没有可拍的现场）。
3. **风格**：用户记住他的表达气质，用 3 个词写（例如「直、土、不装」）。
4. **账号议程**：定位能不能被记住，取决于反复讲什么。写 3 个账号议程——这个号以后反复讲的 3 件事，每件附 1 个例子选题（不展开写）。

### 第六步：一句话定位与交付

先写一句话定位：

> 在<用户>眼里，我是<区域／类别>里<唯一／第一个>做<差异>的<人设>。

**「唯一／第一个」要有依据**：主空位的「没人占」是用户亲自查过的，才能写「唯一／第一个」；还是【待查】时，推荐不带比较的版本（例如「当过 8 年监理、专盯老房水电防水的装修老板」），带「第一个」的版本只能作为备选，并注明查过再用。

**职业介绍检查**：在句子里找主空位的差异词（区域、细分、人群、形式、身份或跨界）；找不到，或者去掉职业名后剩下的说不出差异，说明主空位没落进去，回到第四步。卡头「账号定位」在最后一个判断点之前写「未定」，这是预期的。

然后交付：

```markdown
## 账号定位

一句话定位：……
主变现：……
目标用户：……（一个具体的人）
给他的价值：……
主空位：<方向>——<内容>（有人要：…｜没人占：…｜我占得住：…）
人设：帮<谁>说话，反对<什么>
形式与风格：……
账号议程：1. …… 2. …… 3. ……
备选空位：……
【待查】／【待确认】：……

## 怎么验证这个定位（定位是走出来的）

- 前 30 条：只讲上面 3 个议程，不追热点跑题。
- 看什么信号：评论和私信里，来问的是不是「目标用户」；有没有人提到你的差异（例如「是那个只做××的吗」）。
- 第 30 条复盘：来的人和预想不一样，按来的人调整用户定位；差异没人提，换备选空位或换形式。
- 第 60 条：已经发了一批内容，可以用 `li-agenda-setting` 检查账号印象有没有跑偏。
```

## 质量检查

- 一句话定位里是否能找到主空位的差异词？
- 「没人占」还是【待查】时，推荐的一句话定位里是否没有「唯一／第一个」？
- 「同城没人做」之类的判断是否来自用户亲自查过的事实，否则标了【待查】？
- 主空位是否同时写清了三条件依据，且用到了用户的真实经历或资源？
- 是否只留了 1 个主空位，而不是把九个小定位全填满？
- 用户画像、主空位、人设、最终一句话是否都由用户选定？
- 人设里的身份和事件是否都是他本来就有的，没有编造？
- 是否没有承诺播放量、粉丝数和获客数？
- 交付是否包含验证信号和 30／60 条复盘节点？

## 流水线衔接：内容卡与下一步

本技能是李同学「一步一技能」12 步中的第 1 步「账号定位」。单独使用时照常执行上文流程；从 `li` 主入口或上一步「继续」进来时，按下面衔接。

**内容卡**：用户当前工作目录里的 `内容卡_<主题>.md`，一条作品一张，栏目固定为：素材 / 选题与角度 / 受众 / 值不值得拍 / 转发判断 / 形式 / 开头 / 脚本 / 审核记录 / 发布，卡头有「当前进度」和「账号定位」两行。

- 开始前查找 `内容卡_*.md`：有一张就读取，沿用已确认的内容，不让用户重复提交；有多张先问是哪一条；用户粘贴了「交接卡」就以它为准。没有卡时，在用户做出第一个确认后新建，主题先写「<店名>第一条」，空栏目写「（待填）」。新卡开头三行固定为：`# 内容卡｜<主题>`、`> 当前进度：第 1 步 账号定位（<日期>）`、`> 账号定位：<一句话定位；没有写「未定」>`。
- 读卡时：一张卡记录一条作品；账号定位只写在当前这张卡的卡头，不替用户改其他卡。卡头「账号定位」已有内容时，先问用户是重新定位还是沿用。
- 本技能只更新卡头「账号定位」一行（写用户确认的一句话定位），以及卡头「当前进度」；其他栏目只读。完整的定位交付另存为当前目录的 `账号定位_<店名>.md`，供以后每张新卡复用。发现与其他栏目矛盾时告诉用户，由用户决定。只写用户确认过的短结论，不贴完整分析。
- 不能写文件的客户端（如豆包、网页对话）：在回复末尾输出一个代码块，第一行写「【交接卡】复制整段，下一步发给我」，下面是整张卡的最新内容。

**带练模式（默认）**：目标用户、主空位、人设和最终一句话定位由用户确认——到这些判断点必须停下，给出选项和推荐，等用户选。用户选完才更新内容卡并输出下面的结尾。用户回复「继续」时，定位并读取下一步技能的 SKILL.md（宿主已发现的技能路径，或同级目录按机器名称查找），带着内容卡进入；不越过用户的选择自动连跑。

**结尾格式**：

```
✅ 第 1 步完成：账号定位「<用户确认的一句话定位>」
👉 下一步是第 2 步：素材（li-material-mining 素材挖掘），回复「继续」开始
也可以：已经发过一批内容 → 用 li-agenda-setting 检查账号印象 ／ 已经有素材 → 跳到第 3 步选题角度
```
