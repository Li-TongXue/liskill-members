# 开头（第 7 步）

先写开头，再写全稿。开头决定观众留不留下，也决定后面全稿往哪个方向写。本技能按选定结构的开头规则写 3 个开头，由用户选一个。不写全稿。

## 随包材料

- `references/structure-index.md`：结构索引。
- references/structures 目录：每个结构一个文件，文件名就是结构名。读取选定结构的「开头规则」「结构链」和「信息点模板」的第一段。

## 开头指什么

开头是结构的第一段，口播大约 5–15 秒，通常 2–5 句。它要完成该结构「开头规则」里写的任务，并让观众知道继续看能得到什么。

开头只用三种内容：

- 内容卡和对话里用户确认过的素材；
- 写成【待补：……】的占位，标明需要用户补什么；
- 常识类内容，写成【示例，请改成你的】；
- 根据用户描述改写成口语的句子，写成【按你说的意思写的，请改成原话】。

不编造用户的经历、客户案例、数字和原话。

## 固定流程

### 第一步：确认结构和素材

从内容卡的「形式」「选题与角度」「素材」「受众」取得选定结构和素材。

- 没有选定结构：说明开头要跟着结构走，建议先回第 6 步；用户坚持现在写时，请他从索引里点一个结构名。
- 结构文件找不到：如实说明安装可能缺文件，不凭名字猜结构。

### 第二步：读开头规则

读取结构文件，整理出：

- 开头要完成的任务（例如：抛出行业痛点、立一个强观点、交代反常结果）；
- 结构给出的开头句式；
- 开头必须用到的素材，以及哪些已有、哪些缺。

### 第三步：写 3 个开头

3 个开头都遵守同一条开头规则，但勾住人的方式不同。从下面挑 3 种最适合这条素材的：

| 勾法 | 做法 |
|---|---|
| 反常识 | 先说一个和大多数人想法相反的判断 |
| 具体数字 | 用一个真实的数字、时间或金额开场 |
| 冲突 | 先摆出两方的拉扯或一个代价 |
| 提问 | 直接问出目标观众正在纠结的问题 |
| 画面 | 先给一个能看见的现场或动作 |
| 身份 | 先点出「这条是给谁看的」 |

只有用户确认过的数字和事实才能用于「具体数字」「冲突」「画面」。素材不够时换一种勾法，或者用占位，不硬写。

开头规则需要的关键素材缺失、3 个开头会以同一个占位起句时：先问 1 个问题；用户说「先写」时，允许用一句行业里常见的典型说法起句，标【示例，请改成你的】，让 3 个开头保持不同。用户本人的经历、数字和原话仍然不能这样起草。

每个开头按下面格式交付：

```markdown
**开头 A｜勾法：反常识**
（开头原文，2–5 句）

用到的素材：……
待补：……（没有就写「无」）
适合：……；风险：……
```

### 第四步：让用户选

先写一行推荐：「推荐：开头 X，理由：……（一句话）」，然后问：

> 你选哪一个？也可以把两个拼起来，或者直接改你觉得不像你会说的那句。

用户修改后，复述最终版本并确认。用户三个都不满意时，问一句最不满意的地方，再写一轮，最多两轮；仍不满意就保留用户最接近满意的一版，标出问题，进入下一步时交给全稿再调。

### 第五步：交付

```markdown
## 开头

结构：结构名
勾法：……
开头原文：……
待补：……
```

## 质量检查

- 3 个开头是否都遵守了选定结构的开头规则？
- 3 个开头的勾法是否真的不同，而不是同一句换词？
- 是否只用了确认过的素材，缺的地方用了占位？
- 是否没有编造数字、案例和原话？
- 是否由用户选定，并复述了最终版本？

## 流水线衔接：内容卡与下一步

本技能是李同学「一步一技能」12 步中的第 7 步「开头」。单独使用时照常执行上文流程；从 `li` 主入口或上一步「继续」进来时，按下面衔接。

**内容卡**：用户当前工作目录里的 `内容卡_<主题>.md`，一条作品一张，栏目固定为：素材 / 选题与角度 / 受众 / 值不值得拍 / 转发判断 / 形式 / 开头 / 脚本 / 审核记录 / 发布，卡头有「当前进度」和「账号定位」两行。

- 开始前查找 `内容卡_*.md`：有一张就读取，沿用已确认的内容，不让用户重复提交；有多张先问是哪一条；用户粘贴了「交接卡」就以它为准。没有卡时，在用户做出第一个确认后新建，空栏目写「（待填）」。
- 读卡时：「形式」里的选定结构和素材对照直接使用；「素材」「选题与角度」「受众」里已确认的内容直接写进开头，缺什么再问。
- 本技能只更新「开头」（写第五步的交付内容）和卡头「当前进度」；其他栏目只读。发现与其他栏目矛盾时告诉用户，由用户决定。只写用户确认过的短结论，不贴完整分析。
- 不能写文件的客户端（如豆包、网页对话）：在回复末尾输出一个代码块，第一行写「【交接卡】复制整段，下一步发给我」，下面是整张卡的最新内容。

**带练模式（默认）**：选哪个开头由用户决定——到这个判断点必须停下，给出 3 个开头和推荐，等用户选。用户选完才更新内容卡并输出下面的结尾。用户回复「继续」时，定位并读取下一步技能的 SKILL.md（宿主已发现的技能路径，或同级目录按机器名称查找），带着内容卡进入；不越过用户的选择自动连跑。

**结尾格式**：

```
✅ 第 7 步完成：选定开头 <A/B/C>（<勾法>）
👉 下一步是第 8 步：完整脚本（li-script-writing 完整脚本），回复「继续」开始
也可以：回到第 6 步换结构 ／ 再写一组开头
```
