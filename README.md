# liskill-members

liskill 会员技能仓库。通过对话，从真实素材出发，完成内容定位、素材挖掘、选题分析及特定类型的写作与审稿。

适用于支持 Agent Skills 和本地文件读取的工具。不同客户端的安装入口、命令展示和脚本执行能力不同；不能执行脚本的客户端需要在终端完成更新，再按其导入方式重新加载。

## 安装或更新

推荐使用一行命令安装到全局（需要 Node，npx 会自动下载）：

```bash
# Gitee（国内用户）
npx -y skills add https://gitee.com/LTX12/liskill-members.git -g --all

# GitHub（国外用户）
npx -y skills add Li-TongXue/liskill-members -g --all
```

安装完成后，直接在 Agent 中说需求（例如「帮我从今天的工作里找能拍的事」），或使用 `li` 主入口 / 各技能的英文机器名即可。

**更新**：重新运行上面的命令即可更新到最新版本。

> 旧版安装过中文 / 大写名称目录（`Li-*`）的用户，更新后如果发现旧名字的技能还在，把它从技能目录中删除即可（例如删除 `~/.agents/skills/` 下 `Li-` 开头的旧目录），保留 `li-` 开头的新版本。

### 可选：使用 li-update 自动迁移（需要 Git + Python 3.10+）

如果已经安装过旧版本、或希望自动清理旧目录并保留本地修改，可以使用仓库内置的更新器（可选，普通用户不需要）：

```bash
git clone --depth 1 https://gitee.com/LTX12/liskill-members.git liskill-members-update
python3 liskill-members-update/skills/li-update/scripts/update.py --apply
```

Windows 安装 Python 后可将 `python3` 换成 `py -3`。更新器只维护官方 liskill 集合：识别旧目录并迁移、备份后替换、失败回滚、检测本地修改时停止并保留原状。详见 [安装与迁移](docs/installation.md)。

## 开始使用

直接说需求即可，例如“帮我从今天的工作里找能拍的事”“检查这段口播稿有没有画面感”。不确定时使用 `li` 主入口。

机器名称使用小写英文和连字符，目录与 `name` 一致。Codex 可以用 `$li-material-mining`；提供斜杠技能菜单的客户端应以菜单实际展示的命令为准。中文名称用于显示与自然语言表达，不另外承诺注册中文斜杠命令。

| 当前情况 | 可以这样说 |
|---|---|
| 不知道拍什么 | 用 li-material-mining，问问我今天发生了什么 |
| 有话题但太平 | 用 li-conflict-topics，看看这个话题有没有真实冲突 |
| 想知道观众为什么转发 | 用 li-social-currency，判断这个题的分享性 |
| 有一段真实经历想写旁白 | 用 li-story-vlog，把这些材料写成克制的 Vlog |
| 已有稿件要检查表达 | 用 li-eight-audits，检查这段稿子的画面和细节 |

## 技能清单

清单由 `skills.json` 生成，区分业务能力、路由入口与更新工具。Level 1 需要共同补充材料，不保证完整成稿；Level 2 已有内置方法或问答流程，仍须使用真实输入。具体理由见各 Skill 的 `metadata.completion_reason`。

<!-- skills:start -->
按短视频制作流程排序：素材 → 选题 → 用户共鸣 → 文案脚本 → 审核 → 发布。

| # | 阶段 | 调用名 | 中文名称 | 用途 |
|---|---|---|---|---|
| 1 | 入口 | `li` | Li 主入口 | 为 liskill 选择适合当前任务的技能。用户明确调用 li、不知道该用哪个 Li 技能，或一个任务需要多项 Li 能力配合时使用；已明确匹配单个业务技能时直接使用该技能。 |
| 2 | 素材 | `li-material-mining` | 素材挖掘 | 通过逐轮追问，从用户的工作和日常经历中挖掘真实的短视频素材，并形成可拍的选题。用户不知道拍什么、觉得日常没有内容，或希望通过聊天寻找素材时使用；已有明确素材、只需要改稿时不使用。 |
| 3 | 选题 | `li-conflict-topics` | 冲突性选题 | 判断普通话题是否适合以冲突展开，找出主冲突并形成不同力度的选题。用户觉得话题太平、想找张力或把话题推进成题时使用；不强推没有真实分歧的教程和通知。 |
| 4 | 选题 | `li-stasis-topoi` | 修辞学选题法 | 从已有事实和不同解释中识别核心争点，再选择因果、定义、对比等切口形成选题。用户想弄清在争什么或选择争议内容角度时使用；事实尚不清楚时先补材料。 |
| 5 | 选题 | `li-public-issues` | 公共问题升维 | 检验具体事件或个人观察是否具有公共性，用事实和机制假设形成值得讨论的公共问题。用户觉得现象不对劲、想讲清背后机制或让更多人理解其影响时使用；证据不足时不强行扩大结论。 |
| 6 | 用户共鸣 | `li-social-currency` | 社交货币选题判断 | 从观众愿意转给谁、转发如何影响自身形象出发，判断和改造选题的分享性。用户明确关心转发、分享或社交货币时使用；不将转发性等同于整体拍摄价值、获客价值或播放量预测。 |
| 7 | 用户共鸣 | `li-agenda-setting` | 议程设置内容定位 | 分析一组内容会让观众形成什么稳定印象，并给出内容支柱和最小修正建议。用户检查账号长期印象或希望反推内容定位时使用；不用于单条稿件的表达润色。 |
| 8 | 文案脚本 | `li-city-impressions` | 城市印象文案生成 | 从用户对城市的真实观察中，组织误解与事实反转的短视频口播脚本。用户希望讲述城市印象或本地生活体验时使用；缺少真实反转经历时先补素材，不虚构故事。 |
| 9 | 文案脚本 | `li-story-vlog` | 故事事件写作 | 将真实经历或人物关系写成克制、留白的 Vlog 旁白，也可按此文风修改已有稿件。用户要求故事 Vlog、事件旁白或克制叙事时使用；不用于强观点口播、教程或强转化带货。 |
| 10 | 审核 | `li-eight-audits` | 八大审核法 | 对已有中文口播稿或短视频脚本按「八步审核流程」逐条诊断：选题=需求+解决方案、开头5秒勾引、陌生化+普遍性、信息清单、明确的朋友和敌人、植入个人营销点、信息效率、筹码，判断能不能发、卡在哪几步、最致命的缺口，并给出可直接使用的改写示范。用户要求审稿、改文案、判断文案能不能发、增强画面感或流量时使用；不用于从零写作、标题起名、发布合规判断或整体流量归因。 |
| 11 | 发布 | `li-publish-pack` | 发布文案标题封面 | 根据用户提供的逐字稿、选题或素材，为抖音、视频号和小红书生成平台适配的发布标题、发布文案与封面文案。用户写好内容要发布、需要跨平台适配、或问标题/文案/封面怎么写时使用；只写口播脚本或纯审稿时不使用。 |
| 12 | 工具 | `li-update` | 更新 liskill | 检查或更新官方 liskill-members 的安装。用户要求更新、升级或检查 Li 安装状态时使用；仅询问版本或更新方式时先解释，只有明确要求更新才执行写入。 |
<!-- skills:end -->

素材挖掘提供五套随包方法。旧版引用但未取得原文的“相关性”和“新闻价值”扩展不计入当前能力，见 [方法来源](skills/li-material-mining/references/sources.md)。八大审核法已按李老师八步审核流程补全（Level 2），不再使用旧的五步表达检查。

## 后续更新

对 Agent 说“更新 liskill”，或使用正式入口 `li-update`。它只同步上述官方仓库，不运行全局的 `skills update`。成功后按客户端要求重新加载技能或新建对话。

只想检查时说“检查 Li 是否需要更新”；检查不修改安装。没有脚本执行能力时，使用上面的终端升级方式。
