# liskill-members

liskill 会员技能仓库。通过对话，从真实素材出发，完成内容定位、素材挖掘、选题分析及特定类型的写作与审稿。

适用于支持 Agent Skills 和本地文件读取的工具。不同客户端的安装入口、命令展示和脚本执行能力不同；不能执行脚本的客户端需要在终端完成更新，再按其导入方式重新加载。

## 安装或从旧版升级

推荐使用本仓库的专属更新器。需要 Git 和 Python 3.10 或更新版本，在终端执行：

```bash
git clone --depth 1 https://gitee.com/LTX12/liskill-members.git liskill-members-update
python3 liskill-members-update/skills/li-update/scripts/update.py --apply
```

Windows 安装 Python 后可将 `python3` 换成 `py -3`。如果下载目录已存在，请使用另一个空目录名，不要覆盖原目录。

同一方式可用于新装和老会员第一次升级。老版本没有 `li-update`，因此首次升级先运行上面的命令。成功后可以删除下载目录；已安装技能是独立副本，不依赖下载目录。

默认安装到通用的 `~/.agents/skills/`；存在 Claude Code 用户目录时也同步 `~/.claude/skills/`。已识别的 `~/.codex/skills/` 旧 Li 安装迁移到通用目录。其他客户端使用自己的技能导入功能，或明确指定其实际技能目录：

```bash
python3 liskill-members-update/skills/li-update/scripts/update.py --apply --skills-dir "/实际的技能目录"
```

指定目录会替代默认目录选择；可重复传入 `--skills-dir` 同步多个已知目录。不知道目录时先查对应客户端说明，不猜测路径。

已经通过 skills CLI 安装的旧版本通常已被转换为小写目录，可直接由更新器识别。手动复制的旧英文目录也会检查。只有内容与已知官方副本一致，或与上次更新记录一致时才迁移；检测到修改、额外文件或同名其他来源时停止并保留原状。详见 [安装与迁移](docs/installation.md)。

若仅需在独立环境试用单个技能，也可以使用 skills CLI：

```bash
npx -y skills add https://gitee.com/LTX12/liskill-members.git -g --skill li-material-mining
```

CLI 安装由该工具管理，不能代替本更新器的旧名称检查与保护流程。已有自定义改动时优先使用本仓库更新器检查。

## 开始使用

直接说需求即可，例如“帮我从今天的工作里找能拍的事”“检查这段口播稿有没有画面感”。不确定时使用 `li` 主入口。

机器名称使用小写英文和连字符，目录与 `name` 一致。Codex 可以用 `$li-material-mining`；提供斜杠技能菜单的客户端应以菜单实际展示的命令为准。中文名称用于显示与自然语言表达，不另外承诺注册中文斜杠命令。

| 当前情况 | 可以这样说 |
|---|---|
| 不知道拍什么 | 用 li-material-mining，问问我今天发生了什么 |
| 有话题但太平 | 用 li-conflict-topics，看看这个话题有没有真实冲突 |
| 想知道观众为什么转发 | 用 li-social-currency，判断这个题的分享性 |
| 有一段真实经历想写旁白 | 用 li-story-vlog，把这些材料写成克制的 Vlog |
| 已有稿件要检查表达 | 用 li-eight-audits，检查这段稿子的画面和细节 |

## 技能清单

清单由 `skills.json` 生成，区分业务能力、路由入口与更新工具。Level 1 需要共同补充材料，不保证完整成稿；Level 2 已有内置方法或问答流程，仍须使用真实输入。具体理由见各 Skill 的 `metadata.completion_reason`。

<!-- skills:start -->
| 机器名称 | 中文名称 | 类型 | 完成度 | 用途 |
|---|---|---|---|---|
| `li` | Li 主入口 | router | 系统工具 | 为 liskill 选择适合当前任务的技能。用户明确调用 li、不知道该用哪个 Li 技能，或一个任务需要多项 Li 能力配合时使用；已明确匹配单个业务技能时直接使用该技能。 |
| `li-agenda-setting` | 议程设置内容定位 | business | Level 2 | 分析一组内容会让观众形成什么稳定印象，并给出内容支柱和最小修正建议。用户检查账号长期印象或希望反推内容定位时使用；不用于单条稿件的表达润色。 |
| `li-city-impressions` | 城市印象文案生成 | business | Level 1 | 从用户对城市的真实观察中，组织误解与事实反转的短视频口播脚本。用户希望讲述城市印象或本地生活体验时使用；缺少真实反转经历时先补素材，不虚构故事。 |
| `li-conflict-topics` | 冲突性选题 | business | Level 2 | 判断普通话题是否适合以冲突展开，找出主冲突并形成不同力度的选题。用户觉得话题太平、想找张力或把话题推进成题时使用；不强推没有真实分歧的教程和通知。 |
| `li-eight-audits` | 八大审核法 | business | Level 2 | 对已有中文口播稿或短视频脚本按「八步审核流程」逐条诊断：选题=需求+解决方案、开头5秒勾引、陌生化+普遍性、信息清单、明确的朋友和敌人、植入个人营销点、信息效率、筹码，判断能不能发、卡在哪几步、最致命的缺口，并给出可直接使用的改写示范。用户要求审稿、改文案、判断文案能不能发、增强画面感或流量时使用；不用于从零写作、标题起名、发布合规判断或整体流量归因。 |
| `li-material-mining` | 素材挖掘 | business | Level 2 | 通过逐轮追问，从用户的工作和日常经历中挖掘真实的短视频素材，并形成可拍的选题。用户不知道拍什么、觉得日常没有内容，或希望通过聊天寻找素材时使用；已有明确素材、只需要改稿时不使用。 |
| `li-public-issues` | 公共问题升维 | business | Level 2 | 检验具体事件或个人观察是否具有公共性，用事实和机制假设形成值得讨论的公共问题。用户觉得现象不对劲、想讲清背后机制或让更多人理解其影响时使用；证据不足时不强行扩大结论。 |
| `li-social-currency` | 社交货币选题判断 | business | Level 2 | 从观众愿意转给谁、转发如何影响自身形象出发，判断和改造选题的分享性。用户明确关心转发、分享或社交货币时使用；不将转发性等同于整体拍摄价值、获客价值或播放量预测。 |
| `li-stasis-topoi` | 修辞学选题法 | business | Level 2 | 从已有事实和不同解释中识别核心争点，再选择因果、定义、对比等切口形成选题。用户想弄清在争什么或选择争议内容角度时使用；事实尚不清楚时先补材料。 |
| `li-story-vlog` | 故事事件写作 | business | Level 2 | 将真实经历或人物关系写成克制、留白的 Vlog 旁白，也可按此文风修改已有稿件。用户要求故事 Vlog、事件旁白或克制叙事时使用；不用于强观点口播、教程或强转化带货。 |
| `li-update` | 更新 liskill | system | 系统工具 | 检查或更新官方 liskill-members 的安装。用户要求更新、升级或检查 Li 安装状态时使用；仅询问版本或更新方式时先解释，只有明确要求更新才执行写入。 |
<!-- skills:end -->

素材挖掘提供五套随包方法。旧版引用但未取得原文的“相关性”和“新闻价值”扩展不计入当前能力，见 [方法来源](skills/li-material-mining/references/sources.md)。八大审核法目前保留原有五步表达检查，名称与完整方法的核对留待后续内容修订，不将其宣传成已完成的八步审核。

## 后续更新

对 Agent 说“更新 liskill”，或使用正式入口 `li-update`。它只同步上述官方仓库，不运行全局的 `skills update`。成功后按客户端要求重新加载技能或新建对话。

只想检查时说“检查 Li 是否需要更新”；检查不修改安装。没有脚本执行能力时，使用上面的终端升级方式。
